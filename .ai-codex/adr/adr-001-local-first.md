# ADR-001: KeyStack — local-first, без облака и без агента-в-браузере

- Статус: принято
- Дата: 2026-06-13

## Контекст
Обсуждали три пути: (1) локальный опенсорс, (2) облачный продукт на домене,
(3) гибрид. Также возникла идея «встроить агента в браузер вместо терминала».

## Решение
**KeyStack остаётся чисто локальным опенсорс-инструментом** (stdio MCP + SQLite +
localhost-дашборд). Облако и агент-в-браузере — отклонены.

## Обоснование
- Аудитория = пользователи Claude Code / Codex, т.е. технари. Они умеют ставить
  локальное; облако (синхра/шеринг) даёт им мало. Облако ради облака — лишние
  расходы и сложность без выгоды. (Контраст с n8n, где аудитория не-технари.)
- HTML-витрину одинаково легко открыть на localhost и на домене → домен не нужен.
- «Агент в браузере» требует контейнер/сандбокс на пользователя — это отдельный
  продукт уровня Cursor/Replit/bolt, scope ×100, конкуренция с гигантами. Отклонено.

## Последствия
- Стек остаётся: Node+TS, stdio MCP, better-sqlite3, Fastify-дашборд (localhost).
- Для «показать на домене» — максимум статичный лендинг + видео-демо (без бэка).
- Цель проекта неизменна: контент / аудитория / GitHub-звёзды, не SaaS.
