## Инвентарь (что уже построено — НЕ переизобретать)

1. **Генератор карт** — `architect-portfolio/scripts/flowmap/` (generate/scan-architecture/scan-ui-flow/capture-ui): сканирует проект → `.flowmap/` артефакты (architecture.json: сервисы/БД/API + edges; ui-flow.json + runtime-ui.json со скриншотами и вердиктами nav-ok/nav-broken/dead; flowmap.mmd Mermaid). Вызывается из /sync ШАГ 5b. Уже умеет диагностику «всё ли работает» статически.
2. **Excalidraw-рендер в стиле Miro владельца** — portfolio admin, вкладка Flows, версия v7 утверждена 08.07 (зоны поверх реальных кнопок на retina-скриншотах), НЕ закоммичена, ждёт визуальной проверки владельца на пилоте SpotBench.
3. **keystack-дашборд** — кросс-проектный хаб (30 проектов, health, спеки), но без карт.
4. **Телеметрия «Борт»** (spec-fleet-telemetry) — источник живых статусов; ждёт стори 0 владельца.

## Что делает (поведение)

**Фаза A — карта всех проектов в keystack (без блокеров, делается сразу):**
- В keystack-дашборде у каждого проекта с существующей `.flowmap/` папкой появляется вкладка/страница «Карта» (`/map/:slug`): рендер `flowmap.mmd` (Mermaid, локальный vendored js — дашборд локальный) + сводка вердиктов из ui-flow.json (CRIT/WARN: dead-ссылки, битая навигация, сироты) + метаданные architecture.json (узлы: сервисы, БД, внешние API, стрелки потоков данных).
- keystack ТОЛЬКО читает готовые артефакты по `local_path` (инвариант «источник правды — проект», как со спеками). Нет `.flowmap/` → плашка «карта не сгенерирована, прогони /sync».
- `keystack-scan.sh` дополнительно пишет в projects поле `has_flowmap` + счётчики вердиктов (map_crit, map_warn) → карточка проекта показывает «карта: 2 CRIT» рядом с health_score.

**Фаза B — карта покрывает ВСЕ проекты (не только Next.js):**
- Прогнать генератор architecture-слоя по всем Track A (он стеконезависим: 3-7 узлов инфраструктуры + рёбра «кто куда ходит»). UI-слой — только Next.js (ограничение генератора, принято).
- Для Flutter/Python/ботов карта = architecture-граф + вердикты телеметрии (фаза C), без скриншотов экранов.

**Фаза C — узлы оживают (после стори 0 «Борта»):**
- Конвенция связывания: id узла в architecture.json ↔ slug чека healthchecks.io / монитора UptimeRobot (`<slug>-<node_id>`); Sentry-проект ↔ проект целиком.
- Ночной (или по требованию) сборщик статусов в keystack: `node_status` таблица (project_slug, node_id, status up|down|degraded|unknown, checked_at) — заполняется API-опросом healthchecks/UptimeRobot (read-only ключи из secret.sh fleet).
- Рендер: узлы Mermaid-карты красятся статусом (зелёный/красный/серый unknown). Итог = ровно запрос владельца: схема узлов проекта, где видно что работает, а что отвалилось.

**Параллельная ветка (не блокирует A):** вердикт владельца по v7-борду портфолио (10 минут глазами) → коммит flowmap-наработок портфолио → дальше их собственный план (v6.1 ромбы логики, v6.2 TG-боты). Excalidraw-визуал остаётся фичей портфолио-админки; keystack-карта — рабочий Mermaid-вид (дёшево, для ежедневного контроля). Один генератор кормит оба.

## Кто использует

Владелец: keystack-дашборд → карточка проекта → «Карта». Агенты: map_crit/map_warn в get_project (реестр). /sync: генерит артефакты как сейчас.

## Edge cases

- [x] `.flowmap/` есть, но протух (старше N дней) → бейдж «устарела, прогони /sync», не ошибка. (N=7, `FLOWMAP_STALE_DAYS`)
- [x] flowmap.mmd битый/пустой → плашка ошибки, дашборд не падает. (тот же код-путь и для «файла нет», внутри существующей `.flowmap/`)
- [ ] Проект без чеков телеметрии → все узлы unknown (серые), не красные. (story 3, BLOCK)
- [ ] Node id без чека по конвенции → unknown; чек без узла → в отчёт сборщика (не терять). (story 3, BLOCK)
- [x] Mermaid vendored локально (дашборд работает офлайн, CDN не тянуть). (`src/dashboard/vendor/mermaid.min.js`, из npm mermaid@11.16.0)
- [ ] Опрос статусов не роняет дашборд при недоступности healthchecks/UptimeRobot (кэш последнего успешного, отметка времени).

## Scope boundary

- НЕ переносить Excalidraw-борд в keystack (остаётся в портфолио-админке).
- НЕ строить свой сканер в keystack (только чтение артефактов генератора).
- НЕ трогать генератор flowmap (его эволюция — спеки портфолио).
- Ромбы серверной логики, TG-бот-рендер — план портфолио (v6.1/v6.2), не сюда.

## Инварианты

| Инвариант | Как |
|-----------|-----|
| Одна величина = один расчёт | карта генерится ОДНИМ генератором (портфолио), keystack — read-модель; статусы — одна таблица node_status, один сборщик |
| Внешние вызовы: путь ошибки | опрос статусов с таймаутом, кэш; сбой → unknown, не крэш |
| Секреты | fleet-ключи из secret.sh, read-only токены где возможно |
