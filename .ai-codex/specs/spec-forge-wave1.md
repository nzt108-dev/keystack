## Что делает (поведение, не реализация)

**1. Схема keystack расширяется** (контракт §2.2 дословно): `projects` + `track('A'|'B')`, `has_architecture`, `has_invariants`, `has_design_md`, `has_ci`, `tests_count`, `tests_green`, `last_audit_date`, `open_crit`, `open_high`, `health_score`. Плюс НОВАЯ таблица `specs`: `project_slug, file (относит. путь), title, stories_total, stories_done, has_block, updated_at, scanned_at` — уникальность (project_slug, file).

**2. `keystack-scan.sh`** (контракт §2.4: детерминированный bash + sqlite3, БЕЗ LLM) — для проекта (или `--all`):
- `has_architecture`: `.ai-codex/architecture.md` существует И >2KB И не содержит `<!-- TEMPLATE -->`; аналогично `has_invariants`; `has_design_md` — только для frontend-стеков; `has_ci` — `.github/workflows/*.yml`.
- `tests_count`: grep-подсчёт по стеку (`def test_|it(|test(|testWidgets(`) по тест-папкам; `tests_green`: прогон тестов с таймаутом 120с если tests_count>0; `--fast` пропускает прогон.
- **Скан спек** (новое): каждый `.ai-codex/specs/*.md` (кроме подпапки `specs/done/`) → title (первая строка `# Spec:`), `stories_total`/`stories_done` (подсчёт ⬜/✅ в таблице «Стори»), `has_block` (строка с `**BLOCK**`, НЕ содержащая «нет»). Upsert в `specs`; исчезнувшие файлы — удаляются из таблицы.
- Пересчёт `health_score` по формуле §4.2: `20·arch + 15·inv + 15·ci + 20·tests_green·min(1, tests_count/20) + 15·audit_fresh + 15·(crit==0 && high==0)`; Track B — только inv+tests, мягче. Спеки в score v1 НЕ входят.

**3. Досев и первый прогон** (контракт §2.5): все проекты из таблицы CLAUDE.md досеяны в keystack (сейчас 10 из ~31), `track` выставлен (A: botseller, crewup, faithly, iwanttoeatair, brieftube, darshan, astro-psiholog, architect-portfolio; остальные B), `keystack-scan.sh --all` прогнан. Скиллы пересинхронизированы `keystack-sync-skills.sh` (из файловой системы; фантомы удалить, sec-check/global-audit добавить).

**4. Генерация вместо ручной синхронизации** (контракт §6): `keystack-export-table.sh` генерирует таблицу «🗂️ Проекты» CLAUDE.md из БД (вызывается из /sync); `ci-babysitter` берёт список репо из keystack (`sqlite3`-запрос), не из хардкода; PreToolUse-хук гейта Фазы 0 читает `~/.claude/track-a-paths.txt`, генерируемый из keystack (warning, не block); LaunchAgent — ежесуточный `keystack-scan.sh --all --fast`.

**5. MCP отдаёт реестр агентам** (новое):
- `get_project` дополнительно возвращает `specs: [{file, title, stories_total, stories_done, has_block}]` и агрегат `open_specs`.
- `list_projects` — счётчик `open_specs` на проект (спека «открыта», если stories_done < stories_total ИЛИ stories_total == 0).
- Session Protocol CLAUDE.md: шаг «Склад спек» получает вторую опору — `get_project(slug)` из keystack показывает то же, что скан файлов (сверка двух источников бесплатна).

## Кто использует / когда вызывается

- Агенты (я и сабагенты): `get_project`/`list_projects` на старте сессии — баннер со спеками/health.
- `/sync` шаг 2.5 (новый): `keystack-scan.sh <path>` + `update_project` (blockers/next_steps).
- `/global-audit` финальный шаг: пишет `last_audit_date, open_crit, open_high`.
- LaunchAgent: ночной `--all --fast`.
- Владелец: дашборд (`npm run dashboard`) — светофор health_score (<50 красный, 50–79 жёлтый, ≥80 зелёный) + колонка открытых спек.

## Edge cases — явно обработать

- [ ] Проект без `.ai-codex/` / без specs/ → нули, не ошибка; строка в keystack остаётся.
- [ ] Спека без таблицы «Стори» (пустая нарезка) → stories_total=0 → считается открытой.
- [ ] Спека с BLOCK «нет.» (с точкой/двоеточием/пробелами) → has_block=false; регистронезависимо. Тест на все 7 существующих спек (6 сегодняшних + шаблон-исключение).
- [ ] Шаблон `~/.claude/templates/ai-codex/spec.md` вне проектов — в скан не попадает по определению; но спека-файл, содержащий `[feature-slug]` (незаполненный шаблон), пропускается.
- [ ] Прогон тестов зависает → timeout 120с → tests_green=0, скан продолжает остальные проекты.
- [ ] Прогон тестов имеет side effects (миграции, докер) → запуск ТОЛЬКО стандартных команд по типу проекта (uv run pytest -q / npm test / flutter test), из корня проекта, без env-инъекций; проект с нестандартной командой — `tests_note` руками, скан не гадает.
- [ ] Два проекта в одной папке-монорепо (brieftube: youtube-parser + yt-saas-frontend) → скан по `local_path` каждой записи, не по слагу.
- [ ] Slug-коллизии при досеве (проект уже есть из 10 старых) → upsert по slug, не дубль.
- [ ] `keystack-export-table.sh` не должен затирать ручные правки остального CLAUDE.md → генерирует ТОЛЬКО между маркерами `<!-- keystack:begin -->` / `<!-- keystack:end -->`; маркеров нет → пишет рядом файл + warning, CLAUDE.md не трогает.
- [ ] БД отсутствует/схема старая при вызове MCP → миграция при старте сервера (существующий паттерн), не крэш.
- [ ] Хук Фазы 0: путь вне всех Track A → молчит; track-a-paths.txt отсутствует → молчит (fail-open, это warning-механизм).
- [ ] LaunchAgent уже загружен при повторной установке → unload/load идемпотентно.

## Что НЕ входит (scope boundary)

- Статусы стори ВНУТРИ спеки не пишутся из keystack (источник правды — файл спеки; keystack только читает). Обновление ✅ в файле — обязанность исполнителя стори.
- Health_score не учитывает спеки (v1 формула = контракт §4.2, менять только через ADR).
- Волна 2+ спеки FORGE (fresh-implementer конвейер и пр.).
- Облачный keystack (ADR-001 local-first остаётся).
- Автогенерация спек, LLM в скане — никогда (детерминизм = контракт).
- Дашборд-редизайн (только колонка open_specs + светофор, если тривиально).

## Затронутые инварианты

| Инвариант | Как соблюдается |
|-----------|-----------------|
| Одна величина = один расчёт | статус спек: файл = источник правды, keystack = read-модель (скан), никто не пишет в оба; таблица проектов CLAUDE.md генерится из БД, не правится руками |
| Консистентность | health_score считается ТОЛЬКО в scan-скрипте (одна формула, одно место) |
| Внешние вызовы: путь ошибки | timeout на тестовые прогоны; ошибка одного проекта не роняет `--all` (собирается в итоговый отчёт скана) |
| Валидация | upsert по slug/file; парсер спек толерантен к мусору (не падает на нестандартном md) |
| Безопасность | скан не читает .env-значения (только имена из .env.example — существующее поведение scan_repo); в БД нет секретов, только keys_ref |
| Данные: UTC | scanned_at/updated_at — ISO UTC |
